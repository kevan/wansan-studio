# 测试用例：V1.3 授权与配置架构验证

> **上下文**：验证“本地优先”授权系统、企业版自动激活、内置 AI 配置安全隔离及 V1.2 -> V1.3 数据迁移。

## 1. 标准版用户 (公测阶段)

### 用例 1.1：全新安装与激活
*   **前置条件**：清理所有存储（DevConsole -> Reset App State）。
*   **操作**：
    1. 启动应用。验证侧边栏底部显示 “TRIAL MODE”。
    2. 进入 设置 -> 授权状态。
    3. 输入一个无效激活码。-> 验证弹出“无效激活码”提示。
    4. 输入有效 Beta 码（可通过 DevConsole 注入 mock 码）。-> 验证弹出“激活成功”提示。
*   **预期结果**：侧边栏变为 “PRO ACTIVE”。`localStorage` 中的 `wansan-settings-v1` 包含 `isActivated: true`。

### 用例 1.2：持久化与离线支持
*   **前置条件**：应用已激活。
*   **操作**：
    1. 关闭应用。
    2. 断开网络连接。
    3. 重新打开应用。
*   **预期结果**：侧边栏依然保持 “PRO ACTIVE”。（验证前端 `localStorage` 对激活状态的持久化有效）。

### 用例 1.3：自定义 AI 配置
*   **操作**：
    1. 设置 -> AI 模型 -> 输入自定义 API Key 和 Model。
    2. 关闭应用。
    3. 重新打开应用。
*   **预期结果**：
    *   前端设置页面正确回显配置。
    *   主进程加密文件 `wansan-ai-config.json` 包含 Model/URL。
    *   系统安全存储 (Keychain) 包含该 Key。

## 2. 企业版用户 (特殊渠道)

### 用例 2.1：自动激活识别
*   **前置条件**：通过 DevConsole 模拟企业版环境（注入 `channel` 字段）。
*   **预期结果**：
    *   侧边栏显示渠道名（如 “DEEPSEEK CORP”）和黑色徽章。
    *   设置 -> 授权状态部分显示为“已激活”且无法手动修改。

### 用例 2.2：全托管 AI 配置 (Managed AI)
*   **前置条件**：模拟主进程注入了内置 AI 配置（`isManaged: true`）。
*   **预期结果**：
    *   设置 -> AI 模型 -> 所有输入框（Provider, URL, Key）变为 **禁用 (Disabled)** 状态。
    *   显示 “企业托管模式” 徽章。
    *   API Key 输入框显示为掩码 `********************`。
*   **操作**：执行一次 AI 对话。
*   **预期结果**：对话成功。验证主进程日志显示使用了内部解密后的 Key。

### 用例 2.3：过期处理
*   **操作**：通过 DevConsole 模拟一个已过期的 `special_expiry`（如 "2020-01-01"）。
*   **预期结果**：侧边栏徽章变为红色 “EXPIRED”，功能受限。

## 3. 版本迁移 (V1.2 -> V1.3)

### 用例 3.1：AI 配置自动迁移
*   **前置条件**：
    *   使用 DevConsole 注入 V1.2 模拟数据。
    *   手动修改 `localStorage`，在 `wansan-settings-v1` 中加入 `baseUrl: "https://old-proxy.com"`。
*   **操作**：刷新或重启应用。
*   **预期结果**：
    *   主进程日志显示 `[Migration] Syncing legacy AI config...`。
    *   检查主进程持久化文件，确认 `https://old-proxy.com` 已同步到后端。
